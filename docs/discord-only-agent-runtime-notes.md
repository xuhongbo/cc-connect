# Discord-only 代理运行说明

## 目的

这份文档专门记录代理运行层的**不可抹平差异**，避免后续为了“统一接口更漂亮”而把真正可运行的行为破坏掉。

总原则只有一句：

> 上层接口可以统一，底层运行模型不能硬统一。

---

## 共通原则

所有代理都遵循以下约束：

1. 继续直接驱动本地 `CLI`
2. 代理层不依赖 `Discord` 类型
3. 图片、文件必须先落盘
4. 逻辑会话与进程对象分离持久化
5. 每个线程同一时间只允许一个活跃轮次

---

## Claude Code

### 本地命令

```text
claude
```

### 运行模型

`Claude Code` 是**长驻进程型**。

关键特征：

- 启动后保留一个长期存活的子进程
- 通过 `stdin` 持续发送消息
- 通过 `stdout` 持续读取事件
- 会话中可能出现权限请求、思考、工具事件

### 设计要求

- 必须有串行写入 `stdin` 的保护
- 必须能检测长驻进程异常退出
- 必须保留会话 `id` 以支持重启后重新 `resume`
- 不要把“当前进程对象”当成唯一会话来源

### 重启恢复

服务重启后：

- 不恢复旧进程对象
- 只恢复逻辑会话 `id`
- 下一次线程消息到来时再重新启动新进程，并通过会话 `id` 续上

---

## Codex

### 本地命令

```text
codex
```

### 运行模型

`Codex` 是**每轮恢复型**。

关键特征：

- 第一轮执行一次 `exec`
- 后续轮次通过 `resume <thread_id>` 继续
- 每轮都会重新拉起子进程
- 子进程结束后，会话逻辑仍然存在

### 设计要求

- 必须把 `thread_id` 作为一等恢复标识持久化
- 必须保留 `reasoning_effort`
- 命令参数顺序不能随意改
- 每轮执行结束后要更新会话 `id` 与最后状态

### 图片与文件

- 图片：先落盘，再通过 `--image`
- 文件：先落到工作目录，再把路径引用拼入提示词

---

## Gemini CLI

### 本地命令

```text
gemini
```

### 运行模型

`Gemini CLI` 也是**每轮恢复型**。

关键特征：

- 每次发送都重新启动一个 `gemini` 进程
- 通过 `--resume <chat_id>` 保持连续性
- 每轮执行应该有超时控制

### 设计要求

- 必须持久化 `chat_id`
- 必须支持轮次级超时
- 临时文件要在本轮结束后清理
- 恢复失败时要允许线程重开绑定

### 图片与文件

- 图片和文件先落临时文件
- 再通过本地引用方式进入提示词

---

## 两类运行模型

新系统必须明确区分两类会话运行时。

### 长驻进程型

代表：

- `Claude`

特征：

- 会话对象长期持有子进程
- 会话对象与进程生命周期强相关

### 每轮恢复型

代表：

- `Codex`
- `Gemini`

特征：

- 会话对象主要持有逻辑会话 `id`
- 每轮启动新进程
- 进程退出不代表逻辑会话失效

---

## 附件处理约束

附件处理必须遵循：

1. `Discord` 层只负责收集附件
2. 代理层或共享工具层负责落盘
3. 不直接把二进制处理逻辑散落到命令层

当前实现目录：

```text
<work_dir>/.cc-connect/attachments/
<work_dir>/.cc-connect/images/
```

临时文件可放在系统临时目录，但必须在回合结束后清理。

## 当前一期已落地的运行层能力

截至当前一期实现：

- `Claude` 已具备真实长驻运行时核心：
  - `stream-json` 输入输出
  - `stdio` 权限回写
  - 会话 `id` 续接
- `Codex` 已具备真实每轮运行时核心：
  - `exec`
  - `exec resume`
  - `reasoning_effort`
  - 图片通过 `--image`
- `Gemini` 已具备真实每轮运行时核心：
  - `--output-format stream-json`
  - `--resume <chat_id>`
  - 每轮超时
  - 图片/文件路径拼入提示

当前仍未完成的主要是更完整的 Discord 端交互管理与展示层，而不是本地 CLI 运行层本身。

## 恢复与降级

### 恢复成功路径

- 数据库中有会话绑定
- 本地代理仍接受该会话 `id`
- 下一轮消息到来时正常恢复

### 恢复失败路径

如果出现：

- `Claude` 无法 `resume`
- `Codex` 的 `thread_id` 无效
- `Gemini` 的 `chat_id` 无效

则必须：

1. 标记当前会话绑定为 `broken`
2. 在线程中明确提示
3. 允许用户执行 `/session restart`

---

## 错误处理约束

代理层必须明确区分以下错误：

- 本地 `CLI` 缺失
- 工作目录不存在
- 输出解析失败
- 会话恢复失败
- 回合超时
- 子进程异常退出

这些错误都必须带上下文，不能只返回模糊的“执行失败”。

---

## 不能做的错误抽象

以下做法在后续实现中应视为高风险：

1. 把 `Claude`、`Codex`、`Gemini` 都包装成同一种底层会话模型
2. 假设所有代理都支持同样的附件参数
3. 假设所有代理都支持同样的恢复语义
4. 把恢复逻辑只放在内存，不落盘关键会话标识

---

## 这份文档的使用方式

任何涉及代理层重构、抽象收敛、接口统一的计划，都应该先对照本文件检查：

- 有没有抹掉关键运行差异
- 有没有把恢复语义做错
- 有没有把附件和目录处理位置放错

如果答案是“有”，就应该先修正文档或修正方案，而不是直接改实现。
